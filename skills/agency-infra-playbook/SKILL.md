# 인프라 운영팀 플레이북

## 담당 범위

ai-hub 저장소 하나다. 수집기, 검색 엔진, 기억 서버, 오케스트레이터, 사무실 화면, 볼트 자동 기록, 상태 백업의 기능 추가·버그 수정·문서 갱신을 맡는다. 다른 저장소(블로그 등)의 코드나 자료는 이 부서가 고치지 않는다.

## 접수 때 꼭 확인할 것

명세 5칸(목표·대상·제외 범위·완료 기준·예산)에 더해 아래 세 가지를 사용자에게 묻는다. 요청 글에 이미 답이 있으면 그 문장을 인용해 확인만 받는다.

1. 무엇이 보이면 끝인가: 사용자가 확인할 화면·명령·출력 한 가지
2. 지금 무엇이 틀렸거나 불편한가: 재현 방법이나 실제 예
3. 건드리면 안 되는 것: 서비스·설정·자료

## 일의 크기 규칙

| 크기 | 기준 | 요청서 | 회의 |
|---|---|---|---|
| 작은 일 | 고칠 파일 1~3개, 설계 쟁점 없음 | 1건 | 열지 않는다 |
| 중간 일 | 고칠 파일 4개 이상이거나 모듈 2개 이상 | 2~4건 | 쟁점이 있을 때만 1회 |
| 큰 일 | 요청서가 5건을 넘음 | 단계로 나눠 단계마다 납품 | 단계마다 필요할 때 |

투입을 늘리기 전에 일을 더 작게 나눌 수 있는지 먼저 본다.

## 요청서 쓰는 규칙

- 요청서 하나는 책임 하나다. owned_paths 가 겹치는 요청서는 차례로 실행한다.
- done 은 시험이나 명령 출력으로 참·거짓을 가릴 수 있는 문장으로 쓴다. "잘 동작한다" 같은 문장은 쓰지 않는다.
- 요청서 경로와 repo 는 절대 경로로 쓴다(`~` 를 쓰면 실행 전에 실패한다).
- forbidden 에 항상 넣는다: 실제 `~/.ai-hub`·실제 볼트에 쓰지 않음(시험은 `AI_HUB_HOME` 을 임시 폴더로), 공개 저장소라 회사 이름·비밀값·사용자 이름이 든 홈 경로 금지, Python 은 표준 라이브러리만, push·삭제·재시작 금지.
- 새 파일·고친 파일은 500줄 이하. 들여쓰기는 탭, 주석·메시지는 한국어, 이름은 영어.
- 시험 명령은 시스템 python3(3.15)과 예약 작업용 python3.14 둘 다에서 통과해야 한다.

## 회의를 여는 경우

- 저장 형식·설정 파일 형식처럼 나중에 바꾸기 비싼 결정
- 공개 저장소에 무엇이 남는지가 걸린 결정
- 서로 다른 모듈의 책임 경계를 정하는 결정

회의는 읽기 전용 의견 수집 1회가 기본이다. 결정 기록에는 채택안·기각 이유·가정·검증 방법을 남긴다.

## 검수 증거

완료 기준마다 아래 중 하나 이상을 붙인다. 하나라도 실패·미검증이면 납품 대기로 넘기지 않는다.

- 전체 단위 시험 수와 통과 여부(python3, python3.14). 단위 시험 통과는 런타임 검증이 아니다.
- 실행해 본 명령과 출력(CLI, `/health` 같은 응답, 종료 코드)
- 화면이 바뀌면 화면 확인 결과(390·768·1280px 가로 넘침 없음)
- 공개 저장소 검사: 새로 추가된 줄에 회사 이름·비밀값 꼴·홈 경로가 없음

## 납품 승인 묶음

승인 전에는 아래를 하나도 실행하지 않는다. 승인 묶음에 대상과 순서를 적는다.

1. 프로젝트 가지를 본 가지(main)에 병합
2. push(공개 저장소 pre-push 검사를 우회하지 않음)
3. 바뀐 서비스 재시작(launchd 서비스 이름과 재시작이 필요한 이유)

## 하지 않는 것

- `🔐` 로 시작하는 노트는 읽지도, 색인하지도, 커밋하지도 않는다.
- 원천(프로젝트 폴더, AI 대화 원문)에 쓰지 않는다.
- 블로그 저장소의 자료·데몬을 고치거나 재기동하지 않는다.
- `hubsetup install --apply` 를 실행하지 않는다. git 훅·검사를 우회하지 않는다.
